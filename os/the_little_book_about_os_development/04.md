# 04 - Output

## Framebuffer / VGA

```asm
global outb

; 輸出一個位元組到 I/O 埠
outb:
    mov al, [esp + 8]    ; 把 data byte 移到 AL (因為 out 指令會從 AL 輸出)
    mov dx, [esp + 4]    ; 把 port number 移到 DX (out 指令使用 DX 作為目標埠)
    out dx, al           ; 把 AL 的值輸出到指定的 port
    ret                  ; 回到呼叫處

global inb

; 從 I/O 埠讀取一個位元組
inb:
    mov dx, [esp + 4]    ; port number 傳入 DX
    in al, dx            ; 從該 port 讀取一個 byte 到 AL
    ret                  ; 回傳結果（注意：回傳值會存在 AL，呼叫者需處理）
```

text 屬性 byte 的格式是：

high（bits 7–4）：background color
low （bits 3–0）：frontground color

cursor position

控制器有兩個 I/O port 負責控制游標位置：

0x3D4: Command port（命令寫入端）
0x3D5: Data port（資料寫入端）

```c
#include "framebuffer.h"

void fb_write_cell_byte(unsigned int i, char c, unsigned char fg, unsigned char bg)
{
    char *fb = FB_BASE_ADDRESS;
    fb[i] = c;
    fb[i + 1] = ((fg & 0x0F) << 4) | (bg & 0x0F);
    // (bg & 0x0F) 取出背景色的低 4 位（背景色最多 16 種顏色）
    // ((fg & 0x0F) << 4) 把前景色放在屬性 byte 的高 4 位（0xF0）
}

void fb_write_cell_location(unsigned int i, char c, unsigned char fg, unsigned char bg)
{
    char *fb = FB_BASE_ADDRESS;
    fb[i * 2] = c;
    fb[i * 2 + 1] = ((bg & 0x0F) << 4) | (fg & 0x0F);
}

void fb_clear()
{
    unsigned int i = 0;
    while (i < FB_WIDTH * FB_HEIGHT * 2)
    {
        fb_write_cell_byte(2 * i, ' ', BLACK, BLACK);
        i = i + 1;
    }
    return;
}

void fb_move_cursor(unsigned char pos)
{
    outb(FB_COMMAND_PORT, FB_HIGH_BYTE_COMMAND); // 設定要寫高位元
    outb(FB_DATA_PORT, ((pos >> 8) & 0x00FF));   // 寫高位元

    outb(FB_COMMAND_PORT, FB_LOW_BYTE_COMMAND); // 設定要寫低位元
    outb(FB_DATA_PORT, pos & 0x00FF);           // 寫低位元
}

void fb_enable_cursor(unsigned char cursor_start, unsigned char cursor_end)
{
    outb(FB_COMMAND_PORT, 0x0A);
    outb(FB_DATA_PORT, (inb(FB_DATA_PORT) & 0xC0) | cursor_start);

    outb(FB_COMMAND_PORT, 0x0B);
    outb(FB_DATA_PORT, (inb(FB_DATA_PORT) & 0xE0) | cursor_end);
}

void fb_disable_cursor()
{
    outb(FB_COMMAND_PORT, 0x0A);
    outb(FB_DATA_PORT, 0x20); // Bit 5 設為 1，表示游標關閉
}
```

## Memory-Mapped I/O（MMIO，記憶體映射 I/O）

MMIO 是一種將 I/O 設備的寄存器映射到 CPU 的記憶體地址空間的方法，讓 CPU 透過標準的讀寫記憶體指令來與 I/O 設備通訊。

1. 特點

- I/O 設備的寄存器與 RAM 位於相同的地址空間。
- CPU 使用標準的 LOAD/STORE 指令來存取 I/O 設備。
- MMIO 可與虛擬記憶體管理（如頁面映射）整合。
- 不需要額外的指令（如 IN 和 OUT），減少指令集的複雜度。
- 受 CPU 緩存機制影響，可能需要標記某些 MMIO 區域為「不可快取」（Uncacheable）。

2. 使用時機

- 記憶體與 I/O 共享同一個匯流排（如 RISC 架構）。
- 需要高效能的 I/O 通訊，例如顯示卡、網卡、儲存裝置等。

## Port-Mapped I/O（PMIO，埠映射 I/O）

PMIO 是將 I/O 設備的寄存器映射到獨立的 I/O 地址空間，透過特殊的指令（如 IN 和 OUT）來存取設備。

1. 特點

- I/O 寄存器不與記憶體共用，有獨立的地址空間。
- CPU 需要使用特定的 IN 和 OUT 指令來存取 I/O 設備。
- 可避免記憶體快取影響 I/O 操作，因為不會經過 CPU 的記憶體管理單元（MMU）。
- 一些 CPU 架構（如 x86）仍廣泛使用 PMIO，尤其是舊版設備（如 COM 埠、LPT 埠）。

2. 使用時機

- 傳統 x86 架構的系統，如 BIOS 設定、舊版周邊裝置（如印表機、串列埠）。
- 需要獨立 I/O 空間來避免記憶體地址衝突的系統。

## MMIO vs PMIO

| 特性            | MMIO                         | PMIO                          |
| --------------- | ---------------------------- | ----------------------------- |
| 地址空間        | 使用記憶體地址               | 獨立的 I/O 地址空間           |
| 存取方式        | LOAD/STORE 指令              | IN/OUT 指令                   |
| 受 CPU 快取影響 | 可能受影響（需標記不可快取） | 不受影響                      |
| 指令需求        | 無需特殊指令                 | 需 IN/OUT 指令                |
| 效能            | 通常較快（受快取影響）       | 較慢（需要特殊 I/O 指令）     |
| 主要應用        | 現代硬體裝置（GPU、SSD）     | 傳統 I/O 裝置（鍵盤、印表機） |
