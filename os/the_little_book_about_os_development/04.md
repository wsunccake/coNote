## Memory-Mapped I/O（MMIO，記憶體映射 I/O）

MMIO 是一種將 I/O 設備的寄存器映射到 CPU 的記憶體地址空間的方法，讓 CPU 透過標準的讀寫記憶體指令來與 I/O 設備通訊。

1. 特點

- I/O 設備的寄存器與 RAM 位於相同的地址空間。
- CPU 使用標準的 LOAD/STORE 指令來存取 I/O 設備。
- MMIO 可與虛擬記憶體管理（如頁面映射）整合。
- 不需要額外的指令（如 IN 和 OUT），減少指令集的複雜度。
- 受 CPU 緩存機制影響，可能需要標記某些 MMIO 區域為「不可快取」（Uncacheable）。

2. 使用時機

- 記憶體與 I/O 共享同一個匯流排（如 RISC 架構）。
- 需要高效能的 I/O 通訊，例如顯示卡、網卡、儲存裝置等。

## Port-Mapped I/O（PMIO，埠映射 I/O）

PMIO 是將 I/O 設備的寄存器映射到獨立的 I/O 地址空間，透過特殊的指令（如 IN 和 OUT）來存取設備。

1. 特點

- I/O 寄存器不與記憶體共用，有獨立的地址空間。
- CPU 需要使用特定的 IN 和 OUT 指令來存取 I/O 設備。
- 可避免記憶體快取影響 I/O 操作，因為不會經過 CPU 的記憶體管理單元（MMU）。
- 一些 CPU 架構（如 x86）仍廣泛使用 PMIO，尤其是舊版設備（如 COM 埠、LPT 埠）。

2. 使用時機

- 傳統 x86 架構的系統，如 BIOS 設定、舊版周邊裝置（如印表機、串列埠）。
- 需要獨立 I/O 空間來避免記憶體地址衝突的系統。

## MMIO vs PMIO

| 特性            | MMIO                         | PMIO                          |
| --------------- | ---------------------------- | ----------------------------- |
| 地址空間        | 使用記憶體地址               | 獨立的 I/O 地址空間           |
| 存取方式        | LOAD/STORE 指令              | IN/OUT 指令                   |
| 受 CPU 快取影響 | 可能受影響（需標記不可快取） | 不受影響                      |
| 指令需求        | 無需特殊指令                 | 需 IN/OUT 指令                |
| 效能            | 通常較快（受快取影響）       | 較慢（需要特殊 I/O 指令）     |
| 主要應用        | 現代硬體裝置（GPU、SSD）     | 傳統 I/O 裝置（鍵盤、印表機） |
