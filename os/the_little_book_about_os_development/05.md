# 05 - Segmentation

在 x86 架構中，Segmentation（區段） 是早期記憶體管理的一種方式。CPU 使用：
一個 Segment Selector（像是 cs, ds, ss 等），加上一個 Offset，組合成一個 Linear Address

- Segment Selector：是一個 index（索引），放在段暫存器（如 cs, ds）裡
- Segment Base：是 實際的地址基底，存在 GDT（Global Descriptor Table）裡面

```
名稱                儲存位置            內容                    用途
Segment Selector    段暫存器（如 ds）   指向 GDT/LDT 中的哪個段  用來定位段描述子
Segment Base        GDT 的某個 entry    段的起始位址            決定從哪個記憶體位置開始存取
```

```
名稱                | 組成方式                          | 意義（作用）
Logical Address     | Segment Selector + Offset         | 程式碼看到的「邏輯位址」
Linear Address      | Segment Base + Offset             | Segmentation 處理後的位址（虛擬位址）
Physical Address    | 透過 Page Table 映射出的位址      | 真正對 RAM/裝置 的記憶體存取地址
```

```
[Logical Address]
   ↓
[Segmentation: Segment base + offset]
   ↓
[Linear Address]
   ↓
[Paging (optional)]
   ↓
[Physical Address]
```

```
名稱 | 組成 | 意義
Logical Address | 段暫存器:偏移量（例如 ds:0x1234） | 是程式看到的地址格式（你在程式碼裡寫的）
Linear Address | 段基底(base) + offset | CPU 做 Segmentation 計算後得到的實際地址


名稱	說明
Logical Address	段選擇器 + 偏移，例如 ds:0x1234，這是程式寫的位址
Linear Address	段基底（由 GDT/LDT）+ offset 得到的線性地址
Physical Address	如果開啟了 Paging，會透過頁表把 Linear Address 轉成 Physical Address
```

`gdt.asm`

```asm
global load_gdt
global load_registers

load_gdt:
	lgdt [esp + 4]
	ret

load_registers:
	mov ax, 0x10
	mov ds, ax
	mov ss, ax
	mov es, ax
	mov fs, ax
	mov gs, ax
	jmp 0x08:flush_cs

flush_cs:
	ret
```

x86 呼叫約定（cdecl）

從 C 呼叫一個函式，例如 load_gdt(...)，發生的事情如下：

1. C compiler 會先把參數壓入 stack（從右到左）
2. 接著 call 指令 壓入 return address
3. 在 load_gdt: 函式執行時，stack 的樣子是：

```
esp --> return address （4 bytes）
esp+4 --> 參數 struct GDT gdt （6 bytes，但當作 8 bytes 傳入）
```

```asm
[esp + 4] ; 跳過 stack 最底的 4 bytes（那是 return address）
          ; esp + 4 是我們 C 語言傳入的參數 的實際位置
```

```c
struct GDT {
    uint16_t size;  // [2 bytes] size
    uint32_t base;  // [4 bytes] base
};
```

呼叫 load_gdt(\*gdt_ptr) 之後 stack

```
esp --> [ return address     ] ; 4 bytes
        [ gdt.size (2 bytes) ]
        [ gdt.base (4 bytes) ]
```

`segment.c`

```c
static struct GDTDescriptor gdt_descriptors[SEGMENT_DESCRIPTOR_COUNT];

void init_descriptor(int index, unsigned int base_address, unsigned int limit, unsigned char access_byte, unsigned char flags)
{
    gdt_descriptors[index].base_low = base_address & 0xFFFF;
    gdt_descriptors[index].base_middle = (base_address >> 16) & 0xFF;
    gdt_descriptors[index].base_high = (base_address >> 24) & 0xFF;

    gdt_descriptors[index].limit_low = limit & 0xFFFF;
    gdt_descriptors[index].limit_and_flags = (limit >> 16) & 0xF;
    gdt_descriptors[index].limit_and_flags |= (flags << 4) & 0xF0;

    gdt_descriptors[index].access_byte = access_byte;
}

void install_gdt()
{
    gdt_descriptors[0].base_low = 0;
    gdt_descriptors[0].base_middle = 0;
    gdt_descriptors[0].base_high = 0;
    gdt_descriptors[0].limit_low = 0;
    gdt_descriptors[0].access_byte = 0;
    gdt_descriptors[0].limit_and_flags = 0;

    struct GDT *gdt_ptr = (struct GDT *)gdt_descriptors;
    gdt_ptr->address = (unsigned int)gdt_descriptors;
    gdt_ptr->size = (sizeof(struct GDTDescriptor) * SEGMENT_DESCRIPTOR_COUNT) - 1;
    // sizeof(struct GDTDescriptor) = 8（每個 GDT descriptor 是 8 bytes）
    // SEGMENT_DESCRIPTOR_COUNT = 3（定義 null、code、data 三個）

    init_descriptor(1, SEGMENT_BASE, SEGMENT_LIMIT, SEGMENT_CODE_TYPE, SEGMENT_FLAGS_PART);
    init_descriptor(2, SEGMENT_BASE, SEGMENT_LIMIT, SEGMENT_DATA_TYPE, SEGMENT_FLAGS_PART);

    load_gdt(*gdt_ptr);
    load_registers();
}
```

Segment Registers

```
CS =0008 00000000 ffffffff 00cf9a00 DPL=0 CS32 [-R-]

CS = 0008      Segment selector（GDT 中 index 為 1 的項目）
00000000       Base address（段起始地址）
ffffffff       Segment limit（段大小）
00cf9a00       Raw descriptor flags（高 32-bit）
DPL=0          Descriptor Privilege Level（權限 0，kernel）
CS32           Segment type（32-bit Code Segment）
[-R-]          權限標記（Readable）

✅ Selector = 0x0008
GDT index = 0x08 / 8 = 1
代表 Code Segment Descriptor

✅ Base = 0x00000000
segment 起始地址 → 跟 init_descriptor() 設定的一樣

✅ Limit = 0xFFFFFFFF
代表段最大是 4 GB（實際上是：0xFFFFF << 12 + 0xFFF）

✅ Flags = 0x00cf9a00
（只看中間 32 bits）：
0x9A (10011010) → Access Byte（bits 40~47）
  1（P）Present
  00（DPL）= 0
  1（S）= code/data
  1010（type）= Code, executable, readable
0xCF (11001111) → Flags + 高位 limit
  C = 1100 → Granularity = 4KB, Size = 32-bit
  高 4 bits 是 limit[16:19] = 0xF

✅ DPL=0 → kernel mode

✅ CS32 → 32-bit Code Segment

✅ [-R-] → Readable code segment


DS =0010 00000000 ffffffff 00cf9300 DPL=0 DS   [-WA]
✅ Selector = 0x10 → index = 2
✅ Base = 0x00000000
✅ Limit = 0xFFFFFFFF
✅ Flags = 0x00cf9300
  Access Byte = 0x92：
  Present, DPL=0, data segment, writable
  Flags = 0xC（granularity=4K, size=32-bit）
✅ DPL=0, DS, [-WA]：
  Writable (W)
  Accessed (A) = 已被存取過（會自動設）
```
